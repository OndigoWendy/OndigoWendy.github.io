How I approach a problem

Understand. Build. Evaluate.

01 /

Start with the question

Understand the data, the intended use, and what a useful result would mean. Keep the problem clear before choosing the model.

02 /

Make the work inspectable

Use notebooks and small, understandable components to make the reasoning visible. Link the implementation rather than just describing it.

03 /

Be honest about the evidence

Consider the metrics, failure modes, and limits of an experiment. A working prototype is a starting point, not proof of production readiness.
